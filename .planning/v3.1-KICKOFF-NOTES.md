The "landing" identity caps how the team thinks about what to add next. Reframing to "multi-page site" opens room for future pages (doctors, privacy, content hub).

#### Phase 35 — Checkup Fix + Form UX Polish

Options: (a) responsive `<br>` after "и", (b) shorten gradient phrase to "корейских и турецких клиниках" with brand names in subtitle (audit #6, 30 min)

**Effort:** ~2 hr
**Definition of done:** Checkup H1 no longer clips at any tested viewport (1024/1280/1440/1920); all 5 forms show explicit valid state before submit; 0 gender-specific form copy.

---

#### Phase 36 — Shared Layout Primitives (architectural centerpiece)

**Scope:** The key site-foundation phase. Makes "multi-page site" real by eliminating manually-synced footer/header/nav across pages.

- [ ] Extract footer to single source (`partials/footer.html`) — load via `fetch('/partials/footer.html') + innerHTML` on DOMContentLoaded (audit #12)
- [ ] Extract header + mobile menu to `partials/header.html` — same pattern
- [ ] Extract sticky mobile bar to `partials/sticky-bar.html`
- [ ] Add `aria-current="page"` active-state logic that sets on matching nav link after header injection (audit #10, currently only contacts.html has this)
- [ ] Update build pipeline: partials must exist at deploy time (document in README)
- [ ] Remove the 5 duplicate footer variants, 5 duplicate headers, 5 duplicate sticky bars
- [ ] Verify: adding a new blank page (`test.html`) to navigation requires 0 edits to existing pages
- [ ] Fallback strategy: if JS disabled, inline the footer/header directly (server-side include at build time) — evaluate during planning

**Effort:** ~3 hr
**Definition of done:** 6 pages share 1 footer, 1 header, 1 sticky-bar source. Adding a 7th page does not require editing any existing page's footer/header markup. `aria-current="page"` works on every nav item across every page.
**Architectural importance:** This phase is the explicit deliverable for the "multi-page site" reframe. Without it, v3.2+ page additions will be paper cuts.

#### Phase 37 — Site Metadata & Hygiene

**Scope:** Site-level SEO + a11y polish that becomes more important as page count grows.

- [ ] Generate `sitemap.xml` for all 6 pages with correct `<lastmod>` dates — serve from root
- [ ] Review `robots.txt` — ensure sitemap reference, allow all production pages, disallow `/partials/`
- [ ] Audit canonical URLs across all 6 pages for correctness
- [ ] 404.html H1 upgrade from `text-3xl font-extrabold` → `text-5xl md:text-6xl lg:text-7xl` (match other pages, audit #11)
- [ ] 404.html body copy rewrite: generic "Возможно, страница была перемещена или удалена." → "Эту страницу либо перенесли, либо она ещё не появилась. Откройте главную или напишите координатору."
- [ ] Meta description consistency audit across all pages (unique, 150–160 chars, includes primary keyword)
- [ ] Replace country flag inline SVGs with a real flag icon set (circle-flags or similar, audit #14) — on online-consultations.html country list

**Effort:** ~1.5 hr
**Definition of done:** `sitemap.xml` valid and deployed; 404 page matches design system; all meta descriptions audited; flags are recognizable.
