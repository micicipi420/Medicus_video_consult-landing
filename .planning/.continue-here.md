## Critical Anti-Patterns

| Pattern | Description | Severity | Prevention Mechanism |
|---------|-------------|----------|---------------------|
| Bash cwd drift into worktree | My shell's cwd silently moved into `agent-aeac346e` (40-03 worktree) without an explicit `cd`, so `git merge worktree-agent-acbcd926` landed on the wrong branch. Recovered via `cd` back + `git merge --ff-only`, but cost a round-trip of investigation. | advisory | Prefix every git merge command with `cd /absolute/path/to/repo` when worktrees exist, OR run `pwd` + `git rev-parse --abbrev-ref HEAD` immediately before any merge operation. |
| `phase complete` CLI misses bold-format checkboxes | The CLI updates Progress tables and plan checkboxes inside Phase Details sections, but does NOT flip `- [ ] **Phase N:** ` items in the top-of-roadmap active-milestone listing. Also does not flip REQUIREMENTS.md requirement checkboxes. Silent drift. | advisory | Before `/gsd-complete-milestone`, grep ROADMAP.md for `^- \[ \] \*\*Phase` in active-milestone sections and REQUIREMENTS.md for `^- \[ \]` requirement items — flip them manually if they represent work that's already shipped. |
| `milestone complete` CLI auto-extract produces garbage one-liners | Phase 39 SUMMARY files lacked a clean `one_liner` frontmatter field, so the CLI extracted `"Found during:"` as the accomplishment. Required hand-rewriting the MILESTONES.md entry. | advisory | When reviewing a CLI-generated MILESTONES.md entry, skim for placeholder strings like `"Found during:"`, `"TBD"`, `"None"`; replace with hand-curated accomplishments if they're low-signal. |
| complete-milestone workflow doc bug (`rm ROADMAP.md`) | The `reorganize_roadmap_and_delete_originals` step tells you to reorganize ROADMAP.md and then `rm .planning/ROADMAP.md`, which contradicts itself. | advisory | Treat as "reorganize + keep ROADMAP.md, delete REQUIREMENTS.md only". The workflow doc needs an upstream fix. |
