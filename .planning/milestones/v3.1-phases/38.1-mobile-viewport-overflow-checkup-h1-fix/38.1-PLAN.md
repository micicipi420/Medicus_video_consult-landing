# Phase 38.1 Plan — Mobile viewport overflow + checkup H1 fix

## Objective

Eliminate horizontal overflow on mobile (375px) across `index.html`, `treatment-abroad.html`, `checkup.html`, `contacts.html`, `404.html`, and fix the `checkup.html` H1 gradient-span overflow at lg desktop. After execution, `scrollWidth === clientWidth` on every page at 320/375/768/1024/1440. This closes RHYTHM-10 and allows v3.1 to be honestly marked shipped.

## Root cause summary (from Playwright measurements)

All overflows share two core patterns:

1. **nbsp over-application** — `&nbsp;` used between list items / long phrases turns multi-word content into single unbreakable tokens. At bold display sizes, these tokens exceed mobile viewport width and force `scrollWidth > clientWidth`.
2. **Unclipped `mesh-bg__blob` decorative backgrounds** positioned with negative offsets (`right-[-10%]`) extend beyond the document's content box and add 10-50px to `scrollWidth`.

Secondary patterns:
3. **`bg-clip-text` gradient spans** on long cross-language phrases (Latin hospital names + Cyrillic connectors) combine badly with nbsp — the whole gradient span becomes one unbreakable box wider than the parent.
4. **SVG `<rect rx="0 0 3 3">`** — invalid attribute syntax (`rx` takes a single length) on 3 flag icons in `treatment-abroad.html`.

## Measured evidence (pre-fix baseline — 2026-04-08)

|------|------------:|---------:|---------------|
| index.html | 815 | 455px | Country-card `<p>` uses `&nbsp;` between every clinic name AND between `&middot;` separators → one 799px unbreakable string per card |

## Tasks (atomic, one-commit-each)

### Task 1 — Fix checkup.html H1 gradient-span overflow (UIREV-NEW-01)

**Files:** `checkup.html`
**Lines:** 128-132
**Current (broken):**
```html
<h1 class="text-5xl md:text-6xl lg:text-7xl font-extrabold mb-6 leading-[1.1] tracking-tight">
  <span class="text-mu-text-900">Проверьте здоровье в&nbsp;</span><br class="hidden lg:block">
  <span class="bg-gradient-to-r from-mu-blue via-mu-accent-blue to-mu-green-600 bg-clip-text text-transparent">Samsung&nbsp;Medical&nbsp;Center и&nbsp;Severance&nbsp;Hospital</span>
  <span class="text-mu-text-900">&nbsp;&mdash;&nbsp;за&nbsp;1&ndash;2&nbsp;дня</span>
</h1>
```

**Fix:**
1. Drop mobile from `text-5xl` to `text-4xl` so the H1 is viewport-safe at 375 (brand names "Samsung Medical Center" won't fit at 48px even with perfect wrapping)
2. Split the gradient span into TWO gradient spans joined by a non-gradient "и" separator span
3. Remove `&nbsp;` bindings WITHIN each hospital name — let them wrap naturally at 320px viewport if needed
4. Keep the structural `<br>` at `lg:block` so desktop layout still breaks after "в" for the two-line hero

**Target markup:**
```html
<h1 class="text-4xl sm:text-5xl md:text-6xl lg:text-7xl font-extrabold mb-6 leading-[1.1] tracking-tight">
  <span class="text-mu-text-900">Проверьте&nbsp;здоровье в</span><br class="hidden lg:block">
  <span class="bg-gradient-to-r from-mu-blue via-mu-accent-blue to-mu-green-600 bg-clip-text text-transparent">Samsung Medical Center</span>
  <span class="text-mu-text-900"> и </span>
  <span class="bg-gradient-to-r from-mu-blue via-mu-accent-blue to-mu-green-600 bg-clip-text text-transparent">Severance Hospital</span>
  <span class="text-mu-text-900"> &mdash; за&nbsp;1&ndash;2&nbsp;дня</span>
</h1>
```

Notes on nbsp choices kept:
- `Проверьте&nbsp;здоровье` — subject+verb binding per feedback memory
- `за&nbsp;1&ndash;2&nbsp;дня` — number phrase binding
- Dropped: all nbsp inside "Samsung Medical Center" and "Severance Hospital" (these are brand-name tokens, wrapping OK on very narrow mobile; bold display size gives enough visual unity)
- Dropped: the `&nbsp;&mdash;&nbsp;` binding — replaced with regular spaces so mobile can break around the em-dash if needed

**Verification:**
- Playwright at 320, 375, 1024, 1440: `h1.scrollWidth === h1.clientWidth` AND `document.documentElement.scrollWidth === document.documentElement.clientWidth`
- Visual: hospital names render with intended gradient, "и" connector in body text color

**Commit:** `fix(38.1): split checkup H1 gradient span, unbind hospital-name nbsp (UIREV-NEW-01)`

### Task 2 — Fix index.html clinic country-card nbsp misuse (UIREV-NEW-02)

**Files:** `index.html`
**Lines:** 668-710 (9 country cards, each with a `<p>` containing nbsp-bound clinic lists)

**Current (broken) pattern per card:**
```html
<p class="...">University&nbsp;Clinic&nbsp;of&nbsp;Munich&nbsp;&middot;&nbsp;University&nbsp;Clinic&nbsp;of&nbsp;Freiburg&nbsp;&middot;&nbsp;ATOS&nbsp;Orthopedic&nbsp;Center&nbsp;&middot;&nbsp;Internistisches Klinikum M&uuml;nchen S&uuml;d&nbsp;&middot;&nbsp;M1&nbsp;Pediatric&nbsp;Center</p>
```

**Problem:** Every word including separators `&middot;` is bound by nbsp. Result: the entire paragraph is one unbreakable 799px string.

**Fix:** Keep nbsp ONLY within multi-word clinic names. Separators and inter-clinic spaces become regular spaces so the browser can wrap at every `&middot;`:
```html
<p class="...">University&nbsp;Clinic&nbsp;of&nbsp;Munich &middot; University&nbsp;Clinic&nbsp;of&nbsp;Freiburg &middot; ATOS&nbsp;Orthopedic&nbsp;Center &middot; Internistisches&nbsp;Klinikum&nbsp;M&uuml;nchen&nbsp;S&uuml;d &middot; M1&nbsp;Pediatric&nbsp;Center</p>
```

Apply this transformation to all 9 cards: Germany, Austria, Switzerland, Israel, South Korea, Turkey, UAE, India, (+ any others). The rule is deterministic:
- `X&nbsp;Y&nbsp;Z&nbsp;&middot;&nbsp;A&nbsp;B` → `X&nbsp;Y&nbsp;Z &middot; A&nbsp;B`
- `&nbsp;&middot;&nbsp;` → ` &middot; ` (regular spaces around `&middot;`)

**Verification:**
- Playwright at 375: `document.documentElement.scrollWidth === clientWidth`; each country-card `<p>` has `scrollWidth <= clientWidth`
- Visual at 1440: cards still look tight/typographically disciplined; hospital names don't break mid-name

**Commit:** `fix(38.1): unbind nbsp between clinic names in index country cards (UIREV-NEW-02)`

### Task 4 — Fix 404.html H1 mobile overflow

**Files:** `404.html`
**Lines:** 108

**Current (broken):**
```html
<h1 class="text-5xl md:text-6xl lg:text-7xl font-extrabold text-mu-text-900 mb-4">Страница&nbsp;не&nbsp;найдена</h1>
```

**Problem:** "Страница не найдена" bound by nbsp = 460px unbreakable at `text-5xl` (48px). Mobile viewport is 375px. Overflow by ~85px.

**Design tension:** The nbsp binding is deliberate (subject+verb pair per feedback memory). Removing it would break on "Страница | не найдена" and "Страница" alone fails orphan prevention (1 word, 8 chars — needs 2+ words AND 10+ chars).

**Resolution:** Keep the nbsp binding, drop the mobile font size from `text-5xl` (48px) to `text-4xl` (36px). At 36px, the bound phrase measures ~345px — fits 375 viewport with margin to spare.

**Target markup:**
```html
<h1 class="text-4xl sm:text-5xl md:text-6xl lg:text-7xl font-extrabold text-mu-text-900 mb-4">Страница&nbsp;не&nbsp;найдена</h1>
```

**Verification:**
- Playwright at 320, 375: `h1.scrollWidth === h1.clientWidth`
- Visual at 1024+: H1 unchanged from current

**Commit:** `fix(38.1): drop 404 H1 mobile size to text-4xl to fit viewport (UIREV-NEW-03b)`

### Task 5 — Clip mesh-bg decorative blobs to their hero sections

**Files:** All pages using `.mesh-bg__blob.mesh-bg__blob--2 ... right-[-10%]` — at minimum `contacts.html`, `treatment-abroad.html`, likely `index.html` and `checkup.html` too.
**Scope:** The blob at `.absolute.top-[20%].right-[-10%].w-[50vw].h-[50vw]` extends outside its containing hero by `10% of viewport` = 37.5px at 375px viewport. This pushes `documentElement.scrollWidth` beyond `clientWidth` by the overflow amount.

**Root-cause location:** The `mesh-bg` parent is a section wrapper. It's missing `overflow: clip` (or `overflow-x: clip`) so the negatively-offset child escapes.

**Fix approach:** Add `overflow-x: clip` (NOT `overflow-x: hidden`) to the `.mesh-bg` ancestor class OR the hero section that contains it. `overflow: clip` is the correct primitive here because it doesn't create a new block formatting context and doesn't disable `position: sticky` descendants, unlike `overflow: hidden`.

**Implementation choice:**
- **Option A (preferred):** Add `overflow-x: clip` to `.mesh-bg` in a shared CSS rule (`src/styles/index.css` or wherever the `mesh-bg` class is defined). Single-point fix, all pages benefit.
- **Option B (fallback):** Add Tailwind utility `overflow-x-clip` (or `[overflow-x:clip]` if not in the safelist) to each hero section inline. More edits but more visible in page-level diffs.

Prefer Option A. Grep for `.mesh-bg` in `src/styles/` and `css/` to locate the declaration; if it doesn't exist (it's just utility-only), add it to `src/styles/index.css` under `@layer components`:

```css
@layer components {
  .mesh-bg {
    position: relative;
    overflow-x: clip;
  }
}
```

Then rebuild CSS via `./tailwindcss -i src/styles/tailwind.css -o css/styles.css --minify` (or whatever the project's build command is — check package.json scripts or a Makefile/.sh).

**Verification:**
- Playwright at 375 on all 6 pages: `documentElement.scrollWidth === clientWidth`
- No `position: sticky` regressions on header/mobile menu

**Commit:** `fix(38.1): clip mesh-bg decorative blobs to prevent document overflow (UIREV-NEW-03c)`

### Task 6 — Fix invalid SVG `rx` attributes on treatment-abroad.html flags (UIREV-NEW-04)

**Files:** `treatment-abroad.html`
**Lines:** 336 (Germany), 376 (India — 2 occurrences), 390 (UAE)

**Current (broken):**
```html
<!-- Germany -->
<svg viewBox="0 0 48 32">
  <rect width="48" height="32" rx="3" fill="#000"/>
  <rect y="11" width="48" height="10" fill="#DD0000"/>
  <rect y="21" width="48" height="11" rx="0 0 3 3" fill="#FFCC00"/>  <!-- invalid rx -->
</svg>

<!-- India -->
<svg viewBox="0 0 48 32">
  <rect width="48" height="32" rx="3" fill="#fff"/>
  <rect width="48" height="11" rx="3 3 0 0" fill="#FF9933"/>  <!-- invalid rx -->
  <rect y="21" width="48" height="11" rx="0 0 3 3" fill="#138808"/>  <!-- invalid rx -->
  <circle .../>
</svg>

<!-- UAE -->
<svg viewBox="0 0 48 32">
  <rect width="48" height="32" rx="3" fill="#000"/>
  <rect x="12" .../>
  <rect x="12" .../>
  <rect x="12" .../>
  <rect width="12" height="32" rx="3 0 0 3" fill="#FF0000"/>  <!-- invalid rx -->
</svg>
```

**Fix:** Wrap the inner colored rects in a `<clipPath>` rounded to the outer rect's corner radius. This yields correct per-corner rounding without invalid syntax.

**Target pattern (Germany example):**
```html
<svg viewBox="0 0 48 32">
  <defs><clipPath id="flag-de"><rect width="48" height="32" rx="3"/></clipPath></defs>
  <g clip-path="url(#flag-de)">
    <rect width="48" height="32" fill="#000"/>
    <rect y="11" width="48" height="10" fill="#DD0000"/>
    <rect y="21" width="48" height="11" fill="#FFCC00"/>
  </g>
</svg>
```

Apply the same pattern to India (id `flag-in`) and UAE (id `flag-ae`). Remove all `rx="0 0 3 3"` / `rx="3 3 0 0"` / `rx="3 0 0 3"` attributes; they're replaced by the clipPath parent.

**Verification:**
- Playwright console (`browser_console_messages level=error`) on `treatment-abroad.html`: 0 SVG `rx` errors
- Visual: 3 flags render with correctly rounded corners (uniform 3px radius on all 4 corners — visually identical to before where the rounded base rect was doing most of the work)

**Commit:** `fix(38.1): replace invalid SVG rx shorthand with clipPath on treatment-abroad flags (UIREV-NEW-04)`

## Anti-patterns / explicitly rejected approaches

- **`overflow-x: hidden` on `body` or `html`** — hides the symptom globally, breaks `position: sticky` descendants, and masks any future overflow bugs from surfacing
- **Replacing `&nbsp;` globally with regular spaces** — would break the deliberate subject+verb / number-phrase bindings that are part of the design system (see feedback memory `feedback_nbsp-subject-verb`)
- **Dropping `bg-clip-text` on hospital-name spans** — kills a deliberate visual motif; split-the-span is a less destructive fix
- **Adding new Tailwind tokens** — Phase 38 owns vertical rhythm tokens; this phase only corrects misuse, doesn't introduce new design primitives
- **Renumbering phases / reopening shipped phases 34/35/37/38** — STATE.md says v3.1 shipped; touching them would surprise-revert shipped work
