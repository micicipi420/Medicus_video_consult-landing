### Issues Found (2)

**MISSING-1 (WARN):** `@supports not (backdrop-filter)` fallback for `.card--glass` uses hardcoded `rgba(255,255,255,0.95)` instead of `var(--color-white)`. Safe in practice (dark mode rule at line 427 wins via cascade order), but fragile. **Fix:** replace with `var(--color-white)`.

**MISSING-2 (INFO):** `@media (prefers-color-scheme: dark)` first-visit block defines `--glass-bg` and `--glass-border` dark values but omits `--glass-blur: blur(12px)`. Not a functional defect (value is identical in all blocks), but creates asymmetry. **Fix:** add `--glass-blur: blur(12px)` to prefers-color-scheme block for completeness.

## E2E Flows: 2/4

### Complete Flows (2)
1. **Form submission** — CTA click → form scroll → field fill → submit → API → success state — all phases leave form untouched and functional in both light and dark mode
2. **Dark mode persistence** — Toggle → localStorage → reload → FOUC script reads localStorage → correct theme on repaint — works correctly

### Flow Issues (2)

**BROKEN-1 (WARN):** Initial ARIA state on dark first-visit. The FOUC script correctly sets CSS to dark mode before first paint. However `aria-pressed` is hardcoded `false` and icon is `☀` in HTML — they are corrected to dark-mode values only after DOMContentLoaded fires `initDarkMode()`. On a fast connection this is ~50–100ms; on slow connections or devices, longer. Screen reader users navigating immediately after page load may encounter incorrect ARIA state.

**BROKEN-2 (INFO):** Glass pop on pricing card scroll-reveal. The `.card--glass` element has `backdrop-filter: blur(12px)` which pops in abruptly when `animate-on-scroll.is-visible` transitions opacity from 0→1. The blur effect has no transition (unlike the header which has `transition: backdrop-filter 0.3s ease`). Cosmetic only.
