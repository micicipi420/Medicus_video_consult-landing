  <action>
Create `next/lighthouserc.json` with the Lighthouse CI v0.14+ schema. Key choices:

- **`startServerCommand`**: launches the production build, NOT `next dev`. Dev server has React Strict Mode + HMR overhead and would inflate LCP/TBT artificially. Build with `pnpm --dir next build && pnpm --dir next start --port 3001` (port 3001 to avoid clashing with the long-running dev server humans may have on :3000).
- **`url`**: array of 5 routes. Use absolute URLs against the LHCI-spawned server.
- **`preset: "lighthouse:mobile"`** (LH v11+ default mobile preset — Moto G4, 4× CPU, slow 4G).
- **`numberOfRuns: 3`** — median absorbs cold-start jitter on the first run.
- **`assert.assertions`**: explicit per-metric budgets per AUDIT-01. Use `error` level so any breach exits non-zero by default; we'll capture the failure and waive it manually in summary.md if rationalized.

Final file content:

```json
{
  "ci": {
    "collect": {
      "startServerCommand": "pnpm --dir next build && pnpm --dir next start --port 3001",
      "startServerReadyPattern": "Ready in",
      "url": [
        "http://localhost:3001/",
        "http://localhost:3001/checkup",
        "http://localhost:3001/consultations",
        "http://localhost:3001/treatment-abroad",
        "http://localhost:3001/contacts"
      ],
      "numberOfRuns": 3,
      "settings": {
        "preset": "desktop"
      }
    },
    "assert": {
      "assertions": {
        "largest-contentful-paint": ["error", { "maxNumericValue": 2500 }],
        "cumulative-layout-shift": ["error", { "maxNumericValue": 0.1 }],
        "total-blocking-time": ["error", { "maxNumericValue": 200 }],
        "interactive": ["warn", { "maxNumericValue": 3500 }]
      }
    },
    "upload": {
      "target": "filesystem",
      "outputDir": "../.planning/phases/95-audit-and-verification/lighthouse"
    }
  }
}
```

LHCI's `upload.target=filesystem` writes per-URL reports as `lhr-{N}.html` / `lhr-{N}.json` under `outputDir`. Post-process: rename to per-route slug to make the artifact set self-describing. From the JSON's `requestedUrl` field, derive the slug:

```bash
cd .planning/phases/95-audit-and-verification/lighthouse
for f in lhr-*.json; do
  url=$(node -e "console.log(require('./'+process.argv[1]).requestedUrl)" "$f")
  slug=$(echo "$url" | sed -E 's|http://localhost:3001/?||; s|/$||; s|^$|index|')
  cp "$f" "${slug}.report.json"
  html="${f%.json}.html"
  [ -f "$html" ] && cp "$html" "${slug}.report.html"
done
# Keep only the renamed copies in the committed tree:
rm -f lhr-*.json lhr-*.html manifest.json links.json
```

Each route should have exactly one `.report.html` and one `.report.json`. If LHCI's `numberOfRuns: 3` produced 3 reports per URL, keep only the median run (LHCI's `manifest.json` flags it under `representative: true` — read that to pick the correct file BEFORE the rm step).
