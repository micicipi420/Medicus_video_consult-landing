**3. Create `next/Dockerfile` with three stages:**

**Stage 1 -- `deps`:**
- `FROM node:20-slim AS deps`
- Install `pnpm` globally via `corepack enable && corepack prepare pnpm@latest --activate`
- `WORKDIR /app`
- Copy `package.json` and `pnpm-lock.yaml` only
- Run `pnpm install --frozen-lockfile --prod=false` (need devDependencies for build)

**Stage 2 -- `builder`:**
- `FROM node:20-slim AS builder`
- `WORKDIR /app`
- Copy `node_modules` from deps stage
- Copy all source files (`.dockerignore` controls what enters context)
- Set `ENV NEXT_TELEMETRY_DISABLED=1`
- Run `pnpm run build` (produces `.next/standalone`, `.next/static`, and `public/`)
- Note: `output: 'standalone'` in next.config.ts means the build produces a self-contained `server.js` in `.next/standalone/`

**Stage 3 -- `runner`:**
- `FROM node:20-slim AS runner`
- `WORKDIR /app`
- `ENV NODE_ENV=production`
- `ENV NEXT_TELEMETRY_DISABLED=1`
- `ENV PORT=3000`
- `ENV HOSTNAME=0.0.0.0`
- Create a non-root user: `RUN addgroup --system --gid 1001 nodejs && adduser --system --uid 1001 nextjs`
- Copy from builder: `COPY --from=builder /app/public ./public`
- Create `.next` directory owned by nextjs: `RUN mkdir .next && chown nextjs:nodejs .next`
- Copy standalone output: `COPY --from=builder --chown=nextjs:nodejs /app/.next/standalone ./`
- Copy static files: `COPY --from=builder --chown=nextjs:nodejs /app/.next/static ./.next/static`
- `USER nextjs`
- `EXPOSE 3000`
- `CMD ["node", "server.js"]`

Key details:
- Do NOT install pnpm in runner stage (standalone server.js needs no package manager)
- The standalone output already includes required node_modules -- no separate install needed
- `HOSTNAME=0.0.0.0` is required for the Next.js server to listen on all interfaces inside the container (per D-01)

**1. Replace `docker-compose.yml` (root level) entirely:**

```yaml
services:
  database:
    image: postgres:16-alpine
    restart: unless-stopped
    volumes:
      - pgdata:/var/lib/postgresql/data
    environment:
      POSTGRES_USER: ${POSTGRES_USER:-medicus}
      POSTGRES_PASSWORD: ${POSTGRES_PASSWORD:-medicus-local-dev}
      POSTGRES_DB: ${POSTGRES_DB:-medicus}
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U ${POSTGRES_USER:-medicus}"]
      interval: 10s
      timeout: 5s
      retries: 5

  app:
    build:
      context: ./next
      dockerfile: Dockerfile
    restart: unless-stopped
    ports:
      - "${APP_PORT:-3000}:3000"
    depends_on:
      database:
        condition: service_healthy
    environment:
      DATABASE_URL: postgresql://${POSTGRES_USER:-medicus}:${POSTGRES_PASSWORD:-medicus-local-dev}@database:5432/${POSTGRES_DB:-medicus}
      NODE_ENV: production
    healthcheck:
      test: ["CMD", "node", "-e", "fetch('http://localhost:3000/api/health').then(r=>{if(!r.ok)throw 1}).catch(()=>process.exit(1))"]
      interval: 30s
      timeout: 10s
      retries: 3
      start_period: 40s

volumes:
  pgdata:
```

Key details:
- Remove all Directus services, volumes (directus_uploads, directus_extensions)
- Keep `pgdata` named volume for PostgreSQL persistence (DOCK-01)
- The `app` service builds from `./next` context using the Dockerfile created in Task 1
- `DATABASE_URL` is constructed from Postgres env vars, pointing to the `database` service hostname
- Health check uses Node.js fetch (available in node:20) instead of curl (not installed in node:20-slim)
- `start_period: 40s` gives Next.js time to start before Docker begins health checks
- No `version` key (deprecated in Compose V2)
- Do NOT use `curl` for healthcheck -- node:20-slim does not include curl

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Internet -> app container | External HTTP requests reach Next.js on port 3000 |
| app container -> database container | Internal Docker network, PostgreSQL protocol |
| Docker host -> containers | Host environment variables injected into containers |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-67-01 | Information Disclosure | .env file | mitigate | .env is in .gitignore (already configured); .env.example uses placeholder values only; never commit real credentials |
| T-67-02 | Elevation of Privilege | Next.js container | mitigate | Runner stage uses non-root user (nextjs:nodejs, UID 1001); never runs as root |
| T-67-03 | Denial of Service | health endpoint | accept | /api/health is a simple JSON response with no DB query; low risk; rate limiting deferred to reverse proxy (nginx) |
| T-67-04 | Information Disclosure | health endpoint | accept | Returns only { status, timestamp }; no internal details exposed |
| T-67-05 | Spoofing | PostgreSQL | mitigate | PostgreSQL only accessible within Docker network (no published ports); credentials via env vars |
</threat_model>
