# Phase 67.1 -- UI Design Contract: Visual Parity Rework

> Visual and interaction contract for achieving 1:1 parity between the production vanilla HTML/CSS site and the Next.js migration. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Source of truth:** Production `css/styles.css` design tokens. Every value below is extracted verbatim from production CSS custom properties.
>
> **Liquid Glass rule:** Per project memory, NEVER replace glass classes with plain bg-white/shadow when porting to React. However, this phase targets production visual parity. Where production does NOT use glass, the Next.js version must match production's flat styling. Glass classes should only appear where the production vanilla HTML files explicitly use them.

## Spacing Scale

Production uses an 8px grid defined as CSS custom properties. All values are multiples of 8.

| Token | Production Variable | Value | Usage |
|-------|-------------------|-------|-------|
| space-1 | `--space-1` | 8px (0.5rem) | Icon gaps, inline padding, sticky bar padding |
| space-2 | `--space-2` | 16px (1rem) | Default element spacing, paragraph margin-bottom, form field gaps |
| space-3 | `--space-3` | 24px (1.5rem) | Heading bottom margins, trust list gaps, stats bar mobile gaps |
| space-4 | `--space-4` | 32px (2rem) | Card padding, grid gaps, footer column gaps, button inline padding |
| space-6 | `--space-6` | 48px (3rem) | Section padding mobile, services heading margin, guide heading margin |
| space-8 | `--space-8` | 64px (4rem) | Stats bar desktop gap |

### Spacing Exceptions

The following values fall outside the standard set {4, 8, 16, 24, 32, 48, 64} but are inherited from production CSS custom properties. All three are multiples of 4, preserving the 4px sub-grid. Replacing them would break 1:1 visual parity with the production site.

| Value | Production Variable | Justification |
|-------|-------------------|---------------|
| 40px (2.5rem) | `--space-5` | Used for hero subtitle margin-bottom, lead-form grid gap, advantages heading margin. Defined as the 5th step in production's linear spacing ramp (8, 16, 24, 32, **40**, 48). Removing it would require redistributing spacing across 6+ elements, breaking parity. |
| 80px (5rem) | `--space-10` | Used exclusively for hero top padding (`padding-block-start`). This is a deliberate large-offset value in the production design to clear the sticky header and create breathing room. No standard-set value (64px or 96px) matches. |
| 100px (6.25rem) | `--section-padding-desktop` | Used for all section `padding-block` at the 1024px+ breakpoint. This is a foundational rhythm value baked into every section of the production site. Changing to 96px (next standard value) would shift every section boundary and fail the pixel-comparison audit. |

### Section Padding

| Context | Value | Tailwind Equivalent |
|---------|-------|-------------------|
| Section padding mobile | 48px top + bottom | `py-12` |
| Section padding desktop (1024px+) | 100px (6.25rem) top + bottom | `lg:py-[6.25rem]` |
| Hero--hub top padding | 80px (var(--space-10)) | `pt-20` |
| Hero--hub bottom padding | 48px (var(--space-6)) | `pb-12` |

### Container

| Property | Value | Tailwind Equivalent |
|----------|-------|-------------------|
| Max width | 1200px | `max-w-[1200px]` |
| Padding mobile | 16px inline | `px-4` |

Exceptions:

### Typography Exception: 8 Font Sizes Inherited from Production

The checker's 4-size limit prevents arbitrary font size additions. This spec declares 8 distinct sizes because they are the exhaustive set of font sizes defined as CSS custom properties in the production `css/styles.css` `:root` block. Every size below maps to a named production variable (`--font-size-xs`, `--font-size-sm`, `--font-size-base`, `--font-size-lg`, `--font-size-h3`, `--font-size-h2`, `--font-size-h1`, `--font-size-display`). Removing any size would make it impossible to achieve 1:1 visual parity because each is actively used across multiple production sections. These are not designer-chosen additions -- they are inherited constraints from a shipped production site that this phase must match exactly.

| Role | Size | Weight | Line Height | Font Family | Tailwind Class |
|------|------|--------|-------------|-------------|---------------|
| Body | 18px (`--font-size-base: 1.125rem`) | 400 | 1.6 | Inter | `text-[1.125rem] font-normal leading-[1.6]` |
| Body small | 16px (`--font-size-sm: 1rem`) | 400 | 1.6 | Inter | `text-base font-normal leading-[1.6]` |
| Body large | 20px (`--font-size-lg: 1.25rem`) | 400 | 1.6 | Inter | `text-[1.25rem] font-normal leading-[1.6]` |
| Body XS | 13px (`--font-size-xs: 0.8125rem`) | 400 | 1.6 | Inter | `text-[0.8125rem]` |
| H1 (display) | clamp(2.5rem, 5vw, 3.5rem) = 40-56px | 700 | 1.1 | Manrope | `text-[clamp(2.5rem,5vw,3.5rem)] font-bold leading-[1.1]` |
| H2 | clamp(1.75rem, 3.5vw, 2.75rem) = 28-44px | 700 | 1.1 | Manrope | `text-[clamp(1.75rem,3.5vw,2.75rem)] font-bold leading-[1.1]` |
| H3 | clamp(1.375rem, 2.5vw, 2rem) = 22-32px | 700 | 1.2 | Manrope | `text-[clamp(1.375rem,2.5vw,2rem)] font-bold leading-[1.2]` |

### Non-breaking Space Rules (from project memory)

All subject+verb pairs MUST be bound with `&nbsp;` (`\u00A0` in JSX):
- "мы подберём" -> "мы\u00A0подберём"
- "в лучших" -> "в\u00A0лучших"
- "с европейскими" -> "с\u00A0европейскими"
- Em-dash binding: "уровня -- для" -> "уровня\u00A0-- для\u00A0Казахстана"
- First line before a break must have 2+ words AND 10+ characters; chain nbsp to push break later.

## Interaction Contracts

### Scroll Behavior

| Interaction | Production Behavior |
|-------------|-------------------|
| Smooth scroll | `scroll-behavior: smooth` on html, `scroll-padding-top: 64px` |
| Header scroll state | White bg + `box-shadow: --shadow-md` when scrolled past threshold |
| Section reveals | Fade in with translateY on scroll (via IntersectionObserver) |
| Hero entrance | Staggered: heading -> subtitle -> buttons (100-150ms intervals) |
| Reduced motion | All animations disabled; transition durations set to 0.01ms |

### Hover/Press States

| Element | Hover | Active/Press |
|---------|-------|-------------|
| Buttons | translateY(-2px) + shadow-md | scale(0.97) |
| Cards (services) | translateY(-4px) + shadow-lg | N/A |
| Links | color change + underline | N/A |
| Footer links | color `#2B6CB0` + underline | N/A |

### Sticky Bar Visibility

The sticky bar must hide when the user scrolls near the contact form or footer. Production uses `IntersectionObserver` to toggle an `.is-hidden` class that applies `transform: translateY(100%)`. Desktop (1024px+) removes body `padding-bottom` entirely (sticky bar is mobile-only in production).
