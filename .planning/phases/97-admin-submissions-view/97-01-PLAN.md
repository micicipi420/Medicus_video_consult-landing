<objective>
Gate the entire `/admin/*` route subtree behind an env-token check so that a stranger
hitting `https://medicusunion.kz/admin/submissions` cannot read submission data without
the operator's token. This is per ADM-01 — env-token, no full Auth this milestone.

Purpose: protect operator-only PII (names, phones, descriptions) without standing up
NextAuth / iron-session for a single milestone. Token is compared against either
`?token=` query param or `X-Admin-Token` header. Failure → 401 + redirect to `/`.

Output:
- Server-side `auth.ts` helper with constant-time string comparison
- `app/admin/layout.tsx` server component that calls the helper and short-circuits before
  any child page renders
- `.env.example` documents `ADMIN_TOKEN` with a clear placeholder + instruction
</objective>

Next.js 15 server component request access:
```typescript
import { headers } from 'next/headers';
import { redirect } from 'next/navigation';
// In Next 15 server components: const h = await headers();  // h.get('x-admin-token')
// Search params on layout: layouts do NOT receive searchParams in App Router. Use page-level
// param access OR read query from request URL via headers.get('x-url') is unreliable.
// Solution: use middleware OR access searchParams in the page itself, OR use a layout that
// reads BOTH header (always available) and a one-shot cookie set after first ?token= success.
```

**Decision required at task 0 (checkpoint):** layout-level guard via headers + cookie OR
Next.js middleware (`next/middleware.ts`)? Layout cannot read query string directly in
App Router. Two patterns are viable:

  **Pattern A — Next.js middleware** (`next/middleware.ts`):
    + Sees `request.nextUrl.searchParams.get('token')` AND `request.headers.get('x-admin-token')`
    + Single chokepoint; cleanest separation
    + Runs on Edge runtime — `process.env.ADMIN_TOKEN` available at runtime
    + matcher: `/admin/:path*`

  **Pattern B — Server layout + cookie**:
    - Layout reads `headers().get('x-admin-token')` only (no direct query access)
    - First request with `?token=` lands on a small route handler `/admin/auth?token=...`
      that validates and sets `httpOnly` cookie, then redirects to `/admin/submissions`
    - Layout subsequently reads cookie OR header
    - More moving parts; more code

  **Recommended: Pattern A (middleware)** — fewer parts, supports both auth modes natively.

    **If middleware (Pattern A) — RECOMMENDED:**

    Create `next/middleware.ts`:
    ```typescript
    import { NextRequest, NextResponse } from 'next/server';
    import { checkAdminToken } from '@/app/admin/auth';

    export const config = {
      matcher: ['/admin/:path*'],
    };

    export function middleware(req: NextRequest) {
      const fromQuery = req.nextUrl.searchParams.get('token');
      const fromHeader = req.headers.get('x-admin-token');
      const supplied = fromHeader ?? fromQuery;

      if (!checkAdminToken(supplied)) {
        // Threat T-97-01: do not echo back the supplied token in the redirect URL or
        // any response header. Use a generic redirect to "/" with no diagnostic body.
        const redirect = NextResponse.redirect(new URL('/', req.url));
        return redirect;
      }
      return NextResponse.next();
    }
    ```

    NOTE on the auth.ts import path under Edge runtime: ensure `auth.ts` does not import
    Node-only modules (`crypto.timingSafeEqual` is Node-only). For Edge, swap to a
    web-crypto / manual constant-time loop. Easiest path: have `auth.ts` detect runtime
    via `typeof process !== 'undefined' && process.versions?.node` and branch; OR have a
    separate `auth.edge.ts` that middleware imports. Pick whichever is cleaner —
    document the choice in SUMMARY.

       ```typescript
       import { headers, cookies } from 'next/headers';

       export default async function AdminLayout({ children }: { children: React.ReactNode }) {
         const h = await headers();

         const fromHeader = h.get('x-admin-token');
         const fromCookie = c.get('admin_session')?.value;
         // Cookie holds sha256(token); compare via auth helper that knows both modes
         if (!checkAdminToken(fromHeader) && !checkAdminSessionCookie(fromCookie)) {
           redirect('/');
         }
         return <>{children}</>;
       }
       ```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| public internet → /admin/* | Any unauthenticated visitor; must be denied without correct token |
| operator browser → /admin/* | Trusted once token is verified |
| Nginx/Caddy access log → disk | Reverse proxy may log full URI including ?token= query |
| Browser history → other site visits | Referer header may leak ?token= to outbound third-party requests |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-97-01 | Information Disclosure | middleware/layout response | mitigate | Generic redirect to /; never echo supplied token in response body, headers, or cookie. No diagnostic JSON. No logging of token comparison result. |
| T-97-02 | Spoofing | ADMIN_TOKEN strength | mitigate | .env.example documents `openssl rand -hex 32` (32-byte/64-char secret); guidance comment explicitly forbids reusing the placeholder value. |
| T-97-03 | Information Disclosure | URL referer leak | accept | Operator-acknowledged risk in Task-4 checkpoint. Header path (X-Admin-Token) is documented as production preference. ?token= retained for emergency access. |
| T-97-04 | Information Disclosure | Server access log leak | accept | Self-hosted Nginx logs are operator-controlled and not exposed to third parties. Documented in SUMMARY as a known limitation; future ADM phase may rotate to httpOnly cookie if logs become an issue. |
| T-97-05 | Tampering / Spoofing | constant-time compare | mitigate | auth.ts uses constant-time comparison (timingSafeEqual on Node, manual XOR on Edge) including a same-length dummy compare for length-mismatch path. Test exercises both branches. |
| T-97-06 | Denial of Service | brute-force token guess | accept | 32+ char random secret = 128 bits entropy; brute-force is computationally infeasible without rate limiting. Optional: future phase adds Nginx-level rate limit on /admin/. |
| T-97-07 | Repudiation | no admin audit log | accept | Out of scope for v9.0.1 — read-only view, no destructive operations to audit. Future ADM phase if write paths are added. |
</threat_model>
