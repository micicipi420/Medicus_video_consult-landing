### Task 6: online-consultations.html H1 dangling em-dash fix (AUDIT-06)

**File:** `online-consultations.html:127-131`

**Current state (verified):**
```html
<h1 class="text-5xl md:text-6xl lg:text-7xl font-extrabold mb-6 leading-[1.1]">
  <span class="text-mu-text-900">Мнение немецкого врача&nbsp;&mdash;&nbsp;</span>
  <br class="hidden md:block">
  <span class="bg-gradient-to-r from-mu-blue via-mu-accent-blue to-mu-green-600 bg-clip-text text-transparent">за&nbsp;5&nbsp;дней, без&nbsp;перелёта</span>
</h1>
```

**Issue:** On desktop (`md:` and above), the `<br class="hidden md:block">` forces a break right after `—`, leaving "Мнение немецкого врача —" visibly dangling on the first line with trailing em-dash.

**Change:** Move the em-dash to the start of the second span so it leads the gradient phrase instead of trailing the first phrase:
```html
<h1 class="text-5xl md:text-6xl lg:text-7xl font-extrabold mb-6 leading-[1.1]">
  <span class="text-mu-text-900">Мнение немецкого врача</span>
  <br class="hidden md:block">
  <span class="bg-gradient-to-r from-mu-blue via-mu-accent-blue to-mu-green-600 bg-clip-text text-transparent">&mdash;&nbsp;за&nbsp;5&nbsp;дней, без&nbsp;перелёта</span>
</h1>
```

**Rationale:** Em-dash at start of gradient line reads as "specifying the result" and never dangles. Typographically correct per Russian typography conventions.

**Verification:** Visual check at 320, 768, 1024, 1440, 1920 — no trailing em-dash at end of any line. Em-dash consistently begins the second visible line (on desktop/mobile-wrap).

**Commit message:** `fix(33): online-consultations H1 leading em-dash on gradient phrase (AUDIT-06)`
