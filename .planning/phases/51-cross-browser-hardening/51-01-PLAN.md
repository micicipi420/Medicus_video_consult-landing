  <action>
For each of the 4 glass classes that use var() in -webkit-backdrop-filter, add a hardcoded fallback line IMMEDIATELY BEFORE the existing var()-based line. The cascade rule: Safari reads both -webkit-backdrop-filter lines but keeps the LAST one it can parse. Since Safari cannot parse var(), it falls back to the hardcoded line. Chromium reads both backdrop-filter lines and uses the var()-based one (last valid wins).

**Pattern for each class (light mode):**
```css
-webkit-backdrop-filter: blur(VALUE) saturate(180%) brightness(108%); /* Safari: hardcoded fallback (vars fail in -webkit-) */
-webkit-backdrop-filter: blur(var(--liquid-blur-md)) saturate(var(--liquid-saturate)) brightness(var(--liquid-brightness));
backdrop-filter: blur(var(--liquid-blur-md)) saturate(var(--liquid-saturate)) brightness(var(--liquid-brightness));
```

**Dark mode fallbacks:**
Dark mode overrides --liquid-* tokens via .dark selector in theme.css. Since these are CSS custom property overrides and Safari IGNORES vars in -webkit-backdrop-filter anyway, the hardcoded light-mode fallback is what Safari will always use regardless of .dark class. This is acceptable because:
- The visual difference between light (24px/180%/108%) and dark (28px/160%/115%) blur params is subtle
- Safari users get a working glass effect (not zero effect)
- The alternative (duplicating all 4 classes under .dark with different hardcoded values) adds 40+ lines for marginal visual fidelity

However, if the user's success criteria says "verified by toggling custom properties off in Safari Web Inspector", the hardcoded line IS what they'll see. Add a comment at the top of Section 1 explaining this trade-off:

```css
/* Safari backdrop-filter fallback strategy (Phase 51 / XBRO-01):
   Safari ignores CSS custom properties inside -webkit-backdrop-filter.
   Each glass class has a hardcoded -webkit-backdrop-filter line BEFORE the
   var()-based line. Safari uses the hardcoded values; Chromium/Firefox use
   the var() line. Light-mode values are used as the universal fallback --
   the visual difference vs dark params (28px/160%/115%) is negligible. */
```
