  <action>
Find the focus-visible rule block inside `@layer base`. It is currently:

```css
  a:focus-visible,
  button:focus-visible,
  input:focus-visible,
  select:focus-visible,
  textarea:focus-visible,
  [role="button"]:focus-visible,
  [tabindex]:focus-visible {
    outline: none;
    box-shadow: 0 0 0 2px white, 0 0 0 4px var(--mu-blue-text);
  }
```

Replace the two declarations inside the block (outline: none + box-shadow) with:

```css
    outline: 2px solid var(--mu-blue-text);
    outline-offset: 3px;
    box-shadow: none;
```

The selector list (7 selectors for a, button, input, select, textarea, [role="button"], [tabindex]) MUST remain exactly the same. Only the declaration block changes.

**Why this matters:** CSS `box-shadow` is painted as part of the element's render layer and gets clipped by `mask-image`. CSS `outline` is painted outside the element's box model and is NOT clipped by mask-image or overflow hidden. Phase 42 will apply `mask-image` to all squircle elements, so this must land first.

**Why box-shadow: none is needed:** The `@layer base` rule at the top of theme.css (`* { @apply border-border outline-ring/50; }`) may set outline but does NOT set box-shadow. However, there could be other box-shadow values from utility classes or component styles. Setting `box-shadow: none` explicitly removes the old double-ring pattern and prevents any stray box-shadow from appearing alongside the new outline ring.

**Contrast verification already done by research:** --mu-blue-text = #0E8FB5, contrast ratio ~4.6:1 against white, passes WCAG AA 3:1 minimum for non-text UI components.

**DO NOT modify:**
- The selector list (all 7 selectors must remain)
- Any other rule in @layer base
- The existing `* { @apply border-border outline-ring/50; }` rule
- The reduced-motion guard (already extended in Plan 01)
- Any token added in Plan 01
