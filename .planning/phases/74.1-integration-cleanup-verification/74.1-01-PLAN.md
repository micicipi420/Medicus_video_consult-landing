Append a `@media (prefers-reduced-transparency: reduce)` block to the end of css/styles.css, immediately after the closing `}` of the existing `@media (prefers-contrast: more)` block (which ends at line 2737).

The block must cover production-layer transparency effects: the radial-gradient section backgrounds in `.problem` and `.benefits`, and the decorative `.lead-form-section::before` halo pseudo-element. These are the only elements in production css/styles.css that use non-trivial transparency (the rgba gradient overlays).

Add this block at the very end of css/styles.css:

```css

/* -- Accessibility: Reduced transparency mode (ACC-02) -- */
/* Chrome/Edge 118+ only (progressive enhancement -- other browsers unaffected).
   Strips radial-gradient rgba overlays from section backgrounds and hides
   the decorative lead-form-section halo pseudo-element.
   Solid background-color (var(--color-light)) is preserved on all sections. */

@media (prefers-reduced-transparency: reduce) {
  .problem,
  [data-theme="dark"] .problem {
    background: var(--color-light);
  }

  .benefits,
  [data-theme="dark"] .benefits {
    background: var(--color-light);
  }

  .lead-form-section::before {
    display: none;
  }
}
```

This block:
1. Strips the transparent radial-gradient overlays from .problem and .benefits (both light and dark theme variants), leaving the solid var(--color-light) background intact.
2. Hides the .lead-form-section::before decorative gradient halo (a pseudo-element that is purely decorative transparency).
3. Does NOT touch card backgrounds, button backgrounds, or text colors (those are already fully opaque).
4. Includes a comment noting the browser support caveat (Chrome/Edge 118+, progressive enhancement).

Append after the last `}` on line 2737. The file currently ends with no trailing newline beyond that `}` -- add a single blank line before the new comment block.
  </action>
