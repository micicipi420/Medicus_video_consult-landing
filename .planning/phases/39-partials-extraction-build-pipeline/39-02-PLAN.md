<objective>

Purpose: This is the heart of Phase 39. After this plan, chrome drift becomes structurally impossible — the four `partials/*.html` files are the single source of truth, and any future change to header / footer / sticky-bar / mobile-menu touches one file instead of six. The splicer is the mechanism that makes this safe: it preserves the legitimate per-page variation surface (CTA hrefs, current-page nav styling) via a small, explicit token vocabulary baked into each page's `BUILD:vars` block, so editing a partial cannot accidentally alter per-page values.

<!-- BUILD marker syntax (locked decision from concrete_implementation_hints) -->

Per-page vars block (one per HTML page, placed inside <body> immediately after the opening <body> tag, on its own line as an HTML comment):

  <!-- BUILD:vars CTA_HREF=#contact CTA_LABEL="Оставить заявку" CURRENT_PAGE=index -->

Note: CTA_LABEL contains a space, so it needs quoting. The splicer must handle quoted values. Keep parsing simple — POSIX `read` with manual quote stripping works.

Partial block (one per partial per page):

  <!-- BUILD:header -->
  ...whatever the current chrome HTML is — the splicer overwrites this on every build...
  <!-- /BUILD:header -->

The opening marker line and the closing marker line stay; only the lines between them are replaced.

<!-- Splicer behavior contract -->

Input: $@ = list of HTML files to process. If empty, default to the 6 known pages.
For each HTML file:
  1. Parse the BUILD:vars line (must be exactly one). Extract CTA_HREF, CTA_LABEL, CURRENT_PAGE.
  2. Compute the 11 derived tokens (LOGO_ARIA_CURRENT + 4 NAV_HEADER_* + 4 NAV_MOBILE_*) from CURRENT_PAGE.
  3. For each of the four partial markers (header, footer, sticky-bar, mobile-menu):
     a. Read partials/{name}.html
     b. Substitute every {{TOKEN}} with its value (literal sed-style replacement; tokens never contain regex metacharacters)
     c. Locate the matching <!-- BUILD:{name} --> ... <!-- /BUILD:{name} --> block in the HTML file
     d. Replace the block contents (preserving the marker lines and their indentation)
  4. Write the result back to the HTML file (atomic: write to .tmp, then mv)

Footer has no tokens, so substitution is a no-op for footer — but the splicer should still attempt it uniformly to avoid special cases.

The splicer is idempotent: running it twice in a row produces the same output. This is the byte-identity gate.

Error modes:
  - Missing partials/*.html → fail with clear message and exit 1
  - HTML file missing BUILD:vars block → fail with clear message and exit 1
  - HTML file has BUILD:partial opener without matching /BUILD:partial closer → fail with clear message and exit 1
  - Unknown token in partial (e.g. {{UNKNOWN_TOKEN}}) → leave as-is OR fail; pick one and document it (recommend: leave as-is so partials can use literal {{...}} in CSS values without panicking, but emit a warning)

  <action>
    Create `scripts/build-pages.sh` as a POSIX-sh script (NOT bash-only) using `awk` for the marker state machine. Make it executable (`chmod +x`).

    Behavior contract — implement EXACTLY this:

    **Inputs:**
    - Optional positional args: HTML file paths to process. If none provided, default to `index.html online-consultations.html treatment-abroad.html checkup.html contacts.html 404.html`.
    - Required files: `partials/header.html`, `partials/footer.html`, `partials/sticky-bar.html`, `partials/mobile-menu.html`. If any missing, print `[build-pages] FATAL: missing partials/{name}.html` to stderr and exit 1.

    **Per-page processing pipeline** (inside a `for FILE in "$@"` loop):

    Step 1 — Validate the page has a BUILD:vars block:
       Use `grep -c '^<!-- BUILD:vars '` on the file. If count is not exactly 1, print `[build-pages] FATAL: $FILE has N BUILD:vars blocks (expected 1)` and exit 1.

    Step 2 — Parse BUILD:vars to extract CTA_HREF, CTA_LABEL, CURRENT_PAGE:
       Extract the line: `VARS_LINE=$(grep '^<!-- BUILD:vars ' "$FILE" | head -1)`
       Strip the wrapper: `VARS_BODY=$(echo "$VARS_LINE" | sed 's|^<!-- BUILD:vars ||; s| -->$||')`
       Then parse `KEY=VALUE` pairs. Values may be quoted (e.g. `CTA_LABEL="Оставить заявку"`). Use awk for parsing — POSIX `read` with quote handling is fragile. Example awk approach:
       ```
       eval $(echo "$VARS_BODY" | awk '{
         while (match($0, /[A-Z_]+=("[^"]*"|[^ ]+)/)) {
           pair = substr($0, RSTART, RLENGTH);
           sub(/=("|)/, "=\"", pair);
           if (substr(pair, length(pair)) != "\"") pair = pair "\"";
           print pair;
           $0 = substr($0, RSTART + RLENGTH);
         }
       }')
       ```
       After this, $CTA_HREF, $CTA_LABEL, $CURRENT_PAGE are shell variables. Validate all three are non-empty; if any is empty, print `[build-pages] FATAL: $FILE BUILD:vars missing required key (CTA_HREF/CTA_LABEL/CURRENT_PAGE)` and exit 1.
