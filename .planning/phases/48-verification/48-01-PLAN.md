**VERIFY-01: Contrast Audit**

Step 1 — Extract all text-over-glass pairings by grepping for elements inside .liquid-regular, .liquid-card, .stats-glass, .liquid-btn-secondary containers. For each, identify:
- The text color class (text-mu-text-900, text-mu-text-700, text-mu-text-500, text-mu-blue-text, text-white, etc.)
- The effective background (glass tint + page background bleeding through)

Step 2 — Calculate worst-case contrast ratios. For glass surfaces the effective background is a composite:
- Light mode: --liquid-bg rgba(255,255,255,0.18) over --mu-text-50 (#FBFBFB) = effective bg ~#FBFBFB (very light, almost white)
- Dark mode: --liquid-bg rgba(30,40,60,0.45) over navy #0F1923 base = effective bg ~#1A2233 (dark blue-gray)

Use the WCAG relative luminance formula: L = 0.2126*R + 0.7152*G + 0.0722*B (after sRGB linearization).
Contrast ratio = (L1 + 0.05) / (L2 + 0.05) where L1 is lighter.

Compute contrast for every text color token against both light and dark effective backgrounds:
- --mu-text-900 (#1B212C) on light effective bg (~#FBFBFB): must be >= 4.5:1
- --mu-text-700 (#4A4E5C) on light effective bg: must be >= 4.5:1
- --mu-text-500 (#6B6F80) on light effective bg: must be >= 4.5:1
- --mu-blue-text (#0E8FB5) on light effective bg: must be >= 4.5:1
- white (#FFFFFF) on gradient CTA (from #0E8FB5 to #3B6DD0): must be >= 4.5:1
- For dark mode: same text tokens on dark effective bg (~#1A2233)

Step 3 — Check header scroll state. When .header--scrolled is active:
- Light: --liquid-bg changes to rgba(255,255,255,0.45) — check if nav text contrast changes
- Dark: --liquid-bg changes to rgba(30,40,60,0.6) — check dark nav text contrast

Step 4 — Grep all 6 pages for any inline text color that is NOT a design token (hardcoded hex colors). Flag as potential contrast risk.

**VERIFY-02: Keyboard and Focus Audit**

Step 5 — Verify focus-visible rule in theme.css uses `outline` (not `box-shadow`). Confirm by grepping for the exact rule.

Step 6 — Grep all 6 pages for interactive elements: a[href], button, input, select, textarea, [tabindex], [role="button"]. Count per page.

Step 7 — Check for tabindex values > 0 (anti-pattern that breaks natural tab order). Grep for tabindex="[2-9] or tabindex="[1-9][0-9].

Step 8 — Verify no interactive element has tabindex="-1" unless it is genuinely meant to be removed from tab order (e.g., hidden elements, aria-hidden containers).

Step 9 — Check that squircle mask-image does not clip the focus outline. The focus-visible rule uses outline with outline-offset: 3px. Outline renders outside the element border box, OUTSIDE mask-image clip. Verify by confirming: (a) outline (not box-shadow) is used, and (b) outline-offset is positive. If both true, focus ring is safe from mask clipping.

Step 10 — Check for skip-to-content link: grep for href="#page-content" or similar skip link at top of each page. Document presence/absence.
