2. Create `next/src/components/motion/LazyMotionProvider.tsx` ("use client"):
   - Import `LazyMotion` from "framer-motion" and `domAnimation` from "framer-motion/dom" (tree-shakeable features — this is the key to staying under 8KB gzipped).
   - Export a `LazyMotionProvider` component that wraps `{children}` in `<LazyMotion features={domAnimation} strict>`.
   - The `strict` prop errors if a non-`m` motion component is accidentally used inside the tree, enforcing the lightweight pattern.

3. Create `next/src/components/motion/ScrollReveal.tsx` ("use client"):
   - Import `m`, `useReducedMotion` from "framer-motion".
   - Props interface: `{ children: React.ReactNode; className?: string; delay?: number; }`.
   - Inside the component, call `const shouldReduceMotion = useReducedMotion();`.
   - If `shouldReduceMotion` is true, render a plain `<div className={className}>{children}</div>` with no animation — no transform, no opacity change, nothing. This is the "transform: none" approach from 63-CONTEXT.md, NOT the "duration:0" approach.
   - If motion is allowed, render:
     ```tsx
     <m.div
       initial={{ opacity: 0, y: 20 }}
       whileInView={{ opacity: 1, y: 0 }}
       viewport={{ once: true, amount: 0.15 }}
       transition={{ duration: 0.6, ease: "easeOut", delay: delay ?? 0 }}
       className={className}
     >
       {children}
     </m.div>
     ```
   - The `y: 20` matches the project's established 20px vestibular parameter from 63-CONTEXT.md.
   - `viewport.once: true` means the animation fires once and stays — no re-triggering on scroll back up.
   - `viewport.amount: 0.15` triggers when 15% of the element is visible (matching the current site's `amount: 0.2` from animations.js but slightly earlier to feel responsive).

4. Wire LazyMotionProvider into `next/src/app/layout.tsx`:
   - Import `LazyMotionProvider` from `@/components/motion/LazyMotionProvider`.
   - Wrap the `<main>{children}</main>` in `<LazyMotionProvider>`:
     ```tsx
     <LazyMotionProvider>
       <main>{children}</main>
     </LazyMotionProvider>
     ```
   - Do NOT wrap Header/Footer/StickyBar — those are layout chrome, not animation targets. Only page content inside `<main>` needs the motion context.
   - Keep `<SvgRefractionDefs />`, `<Header />`, `<Footer />`, `<StickyBar />` outside the provider.
  </action>

     ```tsx

       hidden: {},
       visible: {
         transition: {
           staggerChildren: 0.12,  // 120ms between each child — per 63-CONTEXT.md "100-150ms intervals"
           delayChildren: 0.1,     // slight initial delay for page paint to settle
         },
       },
     };

     const itemVariants = {
       hidden: { opacity: 0, y: 20 },
       visible: {
         opacity: 1,
         y: 0,
         transition: { duration: 0.6, ease: "easeOut" },
       },
     };
     ```
   - The container uses `initial="hidden" animate="visible" variants={containerVariants}`.
   - Export `HeroEntrance` (the container) and `HeroEntranceItem` (a child wrapper that applies `itemVariants`).
   - `HeroEntranceItem` renders `<m.div variants={itemVariants} className={className}>{children}</m.div>`.
   - Both use `m.div` (not `motion.div`) because they run inside LazyMotion context.
